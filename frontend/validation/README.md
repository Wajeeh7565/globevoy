# Classic frontend validation

- `validate-*.js`: executable checks. Current regression gates are selected by
  `scripts/run-tests.mjs`; other files check historical release contracts and may
  fail on the newer application.
- `fixtures/`: local browser fixtures. Serve `frontend/` as the web root, then open
  `/validation/fixtures/<filename>.html`. Fixture redirects reach the public page
  URLs, and the partner fixture remains local.
- `releases/`: existing release metadata, legal gate note and original checksum
  manifests. Checksums record historical bytes; they are not regenerated by cleanup.
- `results/`: original recorded results, preserved as evidence.
- `output-path.js`: sends new test output to ignored `.cache/validation/frontend/`
  so running validators never overwrites recorded evidence.

Run current checks from the repository root with `npm run test:frontend`.
PowerShell wrappers live under `ops/frontend/validation/` and discover the frontend
directory from their own location. Historical checksum paths are resolved through
`Resolve-PackagePath.ps1`; changed application bytes still fail historical checks.
